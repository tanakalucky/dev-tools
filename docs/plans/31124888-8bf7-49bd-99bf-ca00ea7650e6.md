### 目的

実際の重複と自作部品を減らす。ディレクトリ構成(`app` は薄い route、`features/json/components` と
`features/json/lib`、テスト隣接)は変えない。

### 範囲

1. 未使用の並行実装 4 ファイルを削除する: `features/json/lib/tokenize.ts`、`validate.ts`、`render.ts`、`limits.ts`
   (約 424 行。`index.ts`・テスト・UI のどこからも import されていない)。
2. 公式の shadcn/ui を導入し、実際に使う 5 部品(button、textarea、checkbox、label、alert)だけを追加する。
   置き場所はルートの `components/ui/` と `lib/utils.ts`(既存の境界規則で shared 層)。
3. `json-tool.tsx` とページの素の要素・独自 CSS クラスを、上の部品と Tailwind の utility に置き換える。
   不要になった `app/globals.css` の独自クラスを削除する。
4. import エイリアス `@/*`(リポジトリルート)を、build(Vite)・型検査(tsconfig)・境界 lint の 3 か所で一致させる。
5. 上に伴う README・仕様の事実の更新。

### 判断と理由(シンプルさの方針)

- 部品は shadcn の公式 CLI が生成する標準のものをそのまま使う。独自のラッパー、hooks、テーマ切り替えは作らない。
- エイリアスは shadcn 標準の `@/` を採る。理由: 今後も公式 CLI で部品を追加でき、生成物の import を手で直さずに済む。
- 境界 lint は検査を弱めない。`@/` をルート相対パスへ解決して既存の規則をそのまま適用し、それ以外の未知のエイリアスは
  引き続き拒否する。標準機能では足りない理由: oxlint には層境界の規則が無く、既存の自作プラグインがその役目を持つため、
  エイリアスの解決をそこへ 1 つ足すのが最小。
- 既存の Vite 設定(vinext と cloudflare のプラグイン)は保持し、Tailwind のプラグインを足すだけにする。SPA 用の雛形へ置き換えない。
- 配色は shadcn 公式の手動インストール手順にある neutral のテーマ CSS(出典と MIT 表示を CSS に残す)。
  テーマ切り替えの仕組みは作らない。現行 CSS の `color-scheme: light dark`(OS 設定に従う明暗)は既存の動作として保持する。
  そのため公式 CSS から 2 点だけ変える: ダーク用トークンを `.dark` クラスではなく `prefers-color-scheme: dark` で適用し、
  `@custom-variant dark` は入れない(Tailwind 既定の `dark:` は OS 連動)。トークンの値は公式のまま。
- 重複キー警告は、以前の橙色の枠を utility 1 つで保つ(公式の alert に warning の variant が無いため)。
- 部品は公式 CLI(shadcn 4.21.4、style `base-nova`)の出力をホスト経由で取得したものを使う。この実行環境からは
  レジストリへ接続できないため。取得物は別の一時領域で生成されたので `cn` の import が npm パッケージ `cn` の直接参照に
  なっている。`components.json` の `utils` エイリアスに合わせて `@/lib/utils` 経由へ直す(CLI がこの設定で出す形と同じ)。
  それ以外の部品のソースは変えない。`lib/utils.ts` は公式手順どおり `cn` の再エクスポートだけにする。
- 境界 lint の規則は基準のまま(追加も緩和もしない)。変えるのは `@/` の解決とそのテストだけ。
  途中で足した「`features/*/lib` から共有 UI への import 禁止」は、承認範囲を超える新規則なので取り消す(PM の判断)。

### 保持する動作(変更・削除しない)

日本語 UI と文言、encoded JSON の 1 階層自動デコードと opt-out、入力の保持、数値とエスケープの無変換、
重複キー警告、サイズ・深さ・出力の上限、処理がすべてクライアント内で完結すること、コピーの競合防止、
ハイドレーションの印(`data-hydrated`)、エラーの `role="alert"` と通知・警告の `role="status"`、各入力のアクセシブルな名前。
